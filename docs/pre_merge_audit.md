# PR #11 pre-merge audit

The audit started at `ca9f2c356fd1a97dd52d6abebbecc077391b0d08`. The historical Linux baseline at `c94601398f1009008ff4b779b0c5a510253b9983` remains unchanged, including its separately captured final readiness evidence. That historical result does not validate subsequent orchestration changes.

## Defects reproduced and corrected

- A fault run could return PASS using an old `USER_PLANE_FAILURE` log even when its current traffic command and collector failed. Fault assertions now read only the run's `fault_logs/` and traffic artifact. A UTC Docker-log boundary is recorded immediately before injection; collection uses that boundary and fails closed. New runs cannot reuse an existing output directory. Traffic probe infrastructure errors are distinguished from an observed ping failure.
- Baseline traffic success previously lacked a mandatory final core gate. After traffic, the harness now requires bounded core initialization/health, current NRF/PFCP associations, and zero restarts through a 30-second window. It then rechecks gNB NGAP, UE registration/session state, and both RAN containers' running/restart state. Final health timestamps and outputs are retained. Fault runs also require a currently healthy baseline before injection, and recovery uses the same final checks.
- Repository file hashes missed effective Compose overrides. Fingerprint schema 2 adds a SHA-256 of the JSON returned by `docker compose --profile ran --profile tools config --format json`, with recursively sorted mapping keys and compact serialization. Compose resolves its supported override files, `.env`, environment interpolation, and `COMPOSE_FILE` inputs. Mapping order is ignored; list order is preserved because command/entrypoint order can be meaningful. Only the digest and effective image references are recorded, not resolved environment contents. Resolution failure blocks execution. Existing commit, repository configuration hashes, and host/runtime identity remain included. Image references are version tags, not immutable image-content identities; changing a registry tag's contents remains a reproducibility limitation.
- Cleanup was armed after mutation commands returned. It is now armed before stop/restart, clsact creation, and filter addition. Restart rollback ensures the service is started. Scoped filter cleanup refuses pre-existing rules, verifies absence after an unsuccessful delete, and preserves an existing clsact. Repeated successful cleanup is a no-op. Apply/cleanup failures remain separately reported; SIGTERM during an active fault triggers rollback, and cleanup is protected from repeated interruption. The Compose runner uses process-group timeout/interruption handling.
- Scenario traffic probes now explicitly set the lab DN target, tunnel, and packet count; standalone exploratory traffic options cannot silently replace the scenario's connectivity oracle.

These changes do not alter subscriber authentication material, the declared lab topology, NF users/capabilities, or the historical evidence. Static/unit results and fresh Linux results must be reported separately.
